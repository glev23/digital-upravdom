# Документация проекта «Цифровой Управдом»

Чат-бот в MAX для жителей многоквартирных домов под управлением УК: житель
описывает аварию своими словами, бот определяет, кто за неё отвечает, создаёт
заявку с нормативным сроком и ссылкой на норму, показывает статус и заранее
предупреждает об отключениях. Трек «Умный город» (Минобрнауки России × MAX).

**Срез 2026-09-21:** идея (ревизия 2) и архитектура (ревизия 3) зафиксированы,
**INIT-001 закрыта** — рабочий каркас (`/health`, `/ready`, Docker, venv).
Следующие `ready`: [SPIKE-001](./tasks/spike-001.md),
[DB-001](./tasks/db-001.md); параллельно без кода —
[MAX-001](./tasks/max-001.md), EVAL-001, RESEARCH-001.

## Как устроена документация

- **Продуктовые решения** принимаются в `idea_and_scope.md`, **технические** —
  в `architecture.md`. Архитектура ссылается на идею, но не переопределяет её.
- **Ничего не удаляется молча.** Изменённое решение фиксируется в разделе
  «История решений» того документа, где оно принято: дата, что изменилось,
  почему.
- **Факты отделены от гипотез.** Утверждения со ссылкой на источник и
  собственные допущения помечаются явно — это прямое требование кейса и
  основа ответов на вопросы жюри.
- **Смоделированные данные обозначаются всегда** — в данных (`is_test_data`),
  в README и в презентации (ограничение №10 кейса).
- **Непроверенный внешний контракт не выдаётся за факт.** Всё о MAX Bot API
  и OpenRouter считается предположением до сверки с актуальной документацией.

## Как продолжить разработку

1. Открыть [progress_dev.md](./progress_dev.md).
2. Взять первую задачу `ready` с закрытыми зависимостями. Если task-файла
   ещё нет — завести его по шаблону из [tasks/README.md](./tasks/README.md).
3. Если `ready` нет — не стартовать `blocked`/`planned` без явного запроса.
4. Выполнить только scope задачи; обнаруженное за его пределами — новая
   строка в очереди, а не расширение текущей задачи.
5. Пройти проверки из task-файла и `bash scripts/check.sh` (после INIT-001).
6. Заполнить «Результат закрытия», обновить статус в task-файле и
   `progress_dev.md`. Остальные документы — только если изменились факты,
   решения, команды или адреса.

Команды запуска здесь намеренно не дублируются. Их единственный источник —
корневой [README.md](../README.md).
