**Обновлено:** 2026-09-22 — основной сценарий (онбординг → классификация →
заявка → статус) закрыт локально; **открытая дыра — CLASSIFY-003**

Этот файл — канонический источник порядка и статусов задач. Если пользователь не
назвал задачу явно, следующей является первая строка `ready` с закрытыми
зависимостями. Одновременно допускается одна основная задача `in_progress`.
Задачи без кода (исследование, данные, документы), отмеченные в разделе
«Параллельность», могут идти параллельно с основной.

Очередь не закрыта: новые задачи добавляются по мере разработки, номер
выбирается так, чтобы сохранить логический порядок (промежуточные номера
допустимы — `65`, `155`).

## Статусы

| Статус | Смысл |
|---|---|
| `planned` | Задача известна, но ещё не разрешена к старту |
| `ready` | Постановка готова, все обязательные зависимости закрыты |
| `in_progress` | Работа выполняется |
| `blocked` | Есть конкретная незакрытая зависимость |
| `done` | Результат реализован и проверен |
| `cancelled` | Задача отменена с сохранением причины |

## Параллельность

- Основная линия кода: INIT-001 → DB-001 → BOT-001 → ONBOARD-001 → FLOW-001.
- Независимо от основной линии, без кода: **MAX-001**, **EVAL-001**,
  **RESEARCH-001**. Их можно вести параллельно с любой задачей.
- MASK-001 и LLM-001 не зависят друг от друга и от DB-001 — можно брать
  после INIT-001, если основная линия упёрлась во внешний блокер.
- DEPLOY-001 не зависит от кода приложения, кроме `/health` из INIT-001.
  Чем раньше он закрыт, тем раньше BOT-001 проверяется вживую.

## Definition of Ready

Задача переводится в `ready`, если:

1. определён наблюдаемый результат и границы scope;
2. указаны связанные разделы idea_and_scope.md / architecture.md;
3. закрыты обязательные зависимости;
4. критерии приёмки и команды проверки воспроизводимы;
5. неизвестный внешний контракт (MAX Bot API, OpenRouter) не выдан за
   подтверждённый.

Если в очереди нет `ready`, основная `blocked`/`planned` задача не стартует
без явного запроса пользователя.

## Definition of Done

1. Реализованы заявленные артефакты и только они.
2. Все критерии задачи подтверждены проверками (автоматическими или ручными).
3. Пройдена единая проверка `bash scripts/check.sh` (после INIT-001).
4. Нет секретов в репозитории, логах и образе.
5. В task-файле заполнен фактический результат.
6. Обновлены `progress_dev.md` и только затронутые документы.
7. Незакрытая часть вынесена в отдельную задачу.
