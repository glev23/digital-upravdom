# KB-002 — Слой документов конкретной УК в базе знаний

| Поле | Значение |
|---|---|
| ID | `KB-002` |
| Статус | `done` |
| Требования | idea_and_scope.md шаг 1 (открытый вопрос о слоях БЗ), шаг 6 (Could Have + «переменная часть» масштабирования); architecture.md §6.1 п. 5 |
| Зависимости | KB-001, RIGHTS-001, CLASSIFY-001 |
| Блокирует | не определено |

## Цель

Житель дома под управлением конкретной УК получает ответ по **её** документам
там, где федеральная норма ответа не даёт («за сколько приедет мастер»,
«должна ли УК менять смеситель»), — со ссылкой на пункт договора управления.
Житель другой УК того же города этого документа не видит.

Это прямое подтверждение главного критерия кейса (масштабирование, 35%):
«ядро — федеральные нормы, переменная часть — документы конкретной УК»
перестаёт быть утверждением на слайде и становится проверяемым поведением.

## Scope

### Входит

- смоделированный договор управления демо-УК в корпусе, с
  `management_company_id` во front-matter;
- подпись ссылки, в которой прямо сказано, что документ тестовый;
- пересборка артефактов `data/kb/` (44 чанка вместо 38);
- флаг `--uk` в `scripts/rights_demo.py` для живого прогона слоя;
- тесты изоляции на реальном артефакте.

### Не входит

- загрузка документов реальной УК (её нет — ограничение №10 кейса);
- админка загрузки документов УК (второй виток тиража, idea_and_scope шаг 6);
- версионирование документов УК отдельно от общего `kb_version`;
- приоритет документа УК над федеральной нормой: слой добавляет, но не
  переопределяет.

## Технические требования

- Механика уже существовала до задачи: `management_company_id` проходит
  чанкер (`chunking.py`), загрузчик (`loader.py`), фильтр поиска
  (`retrieval.py`) и оба вызывающих сервиса — `classifier` берёт УК по дому,
  `rights` по адресату. Задача добавляет данные и проверки, а не механику.
- Фильтр в Qdrant: `management_company_id IS NULL` **или** совпадение. Значит
  чанк без УК виден всем, чанк с УК — только жителям её домов, а дом без УК
  видит только федеральные нормы.
- `_short_title` для нового `source_key` обязателен: без него в подпись
  ссылки попадёт полный `title` документа.
- Содержание документа не может быть хуже федеральной нормы: договор вправе
  уточнять свои сроки и каналы, а не ухудшать нормативные (ПП №354, №416).
  Внутренний срок в п. 4.2 прямо назван внутренним обязательством УК.

## Критерии приёмки

- [x] Вопрос о внутреннем сроке УК находит документ этой УК.
- [x] Житель другой УК того же города этот документ не находит.
- [x] Дом без УК документ не находит.
- [x] Подпись ссылки содержит слова «тестовый документ».
- [x] Вопрос о федеральной норме по-прежнему отвечается нормой, а не договором.
- [x] `scripts/kb_smoke.py` — 19/19 после пересборки корпуса.
- [x] Живой прогон на бесплатной модели: ответ по документу УК и по норме — разные.

## Результат закрытия

**Закрыта 27.09.2026.**

Живой прогон на бесплатной модели `nvidia/nemotron-3-super-120b-a12b:free`,
один и тот же вопрос «за сколько часов приедет мастер после заявки об аварии»:

| Прогон | Ответ | Основание |
|---|---|---|
| с `--uk uk-vahitovskaya` | «в течение двух часов, в нерабочее время — трёх» | Договор управления ООО «УК Вахитовская» (тестовый документ), п. 4.2 |
| без флага | «не позднее 30 минут — локализация» | ПП РФ №416, п. 13 |

Второй вопрос («должна ли УК менять смеситель в квартире») — ответ по п. 4.5
договора; федеральные нормы на него прямого ответа не дают, и до этой задачи
бот честно отказывал.

- Корпус: 38 → 44 чанка, `kb_version` `cb6cd5ca…` → `92ca0e34…`; `load_kb`
  докладывает `docs: 7`.
- `kb_smoke.py` после пересборки — 19/19: документ УК не смещает федеральные
  нормы в топе, потому что в прогоне без УК он отфильтрован, а в прогоне с УК
  вопрос о нормативе всё равно ведёт на норму (отдельный тест).
- Отклонение от постановки: понадобилась правка `scripts/rights_demo.py` —
  без флага `--uk` живую проверку слоя было нечем выполнить.

**Follow-up:**

- **выложено на прод 27.09.2026**: `load_kb OK count=44 docs=7`, живая проверка
  в MAX — на «/права за сколько часов приедет мастер после заявки об аварии»
  бот ответил «в течение двух часов, в нерабочее время — трёх» с основанием
  «Договор управления ООО «УК Вахитовская» (тестовый документ), п. 4.2»;
- `kb_smoke.py` проверяет только федеральный слой: запросы с УК в
  `sanity_queries.json` не выносились, изоляция закрыта тестами;
- для реальной УК понадобится процесс приёмки документов (кто подтверждает
  актуальность) — шаги 5 и 7 чек-листа онбординга в idea_and_scope.
