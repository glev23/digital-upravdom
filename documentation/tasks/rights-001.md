# RIGHTS-001 — Ответы на вопросы о правах жителя со ссылкой на норму

| Поле | Значение |
|---|---|
| ID | `RIGHTS-001` |
| Статус | `ready` |
| Исполнитель | dev-ilya (ветка `dev-ilya`) |
| Требования | architecture.md §6.4 (путь независим от классификации; при недоступности LLM — честное сообщение), §4 («уверенная выдумка»), §10, §11 (маскирование, журналы); idea_and_scope.md MoSCoW (Should Have); кейс — работа с официальными данными, недопустимость выдавать предположение модели за факт |

## Цель

Житель спрашивает не «у меня течёт», а «могут ли отключить горячую воду
на месяц?», «положен ли перерасчёт, если две недели холодные батареи?»,
«за сколько должны предупредить об отключении?» — и получает короткий
ответ человеческим языком **только** на основе пунктов нормативов из базы
знаний, с явными ссылками на эти пункты. Если в базе нет нормы, которая
отвечает на вопрос, — бот честно говорит, что не может ответить, и
подсказывает, куда обратиться. Выдуманная норма в ответе хуже любого
отказа: житель пойдёт с ней в УК или ГЖИ.

## Scope

### Входит

- модуль `src/upravdom/rights/`: определение, что сообщение — вопрос о
  правах, поиск фрагментов, генерация ответа, проверка основания, отказ;
- вход в сценарий из диалога FLOW-001 **до** классификации;
- журнал ответов (миграция);
- тексты, тесты, ручной скрипт проверки на живой модели.

### Не входит

- изменение промпта и схемы классификатора (`classifier/prompt.py`,
  `schema.py`) — там сейчас работает основной разработчик (CLASSIFY-003);
- семантический кэш ответов — follow-up;
- расширение корпуса нормативов (перерасчёт — раздел IX ПП №354 и др.) —
  отдельная задача KB; отсутствие нормы в базе — повод для отказа, а не
  для ответа «из головы» модели;
- юридическая консультация — ответ сопровождается оговоркой.

## Технические требования

**Как отличить вопрос о правах от жалобы — без изменений классификатора.**

1. Явный вход: `/rights <вопрос>`, `/права <вопрос>`, «вопрос: …».
   Команда без текста — подсказка «Напишите вопрос после команды,
   например: /права могут ли отключить горячую воду на месяц?».
2. Узкая эвристика в `rights/detect.py`: вопросительная форма **и**
   начало с оборотов о правах/обязанностях — «могут ли», «имеют ли право»,
   «обязаны ли», «должны ли (меня|нас) предупредить», «положен ли», «какой
   срок», «сколько (можно|дней|часов)», «как (получить|сделать)
   перерасчёт», «куда жаловаться».
   **Не** считаются вопросом о правах и уходят в классификацию: «кто
   должен…», «кто отвечает…», «кому звонить…» — это вопрос «кому», ядро
   продукта (CLASSIFY-001); и любые описания проблемы, даже с «?» в конце
   («опять нет воды?»).
   Отрицательные примеры — обязательная часть тестов.

Проверка выполняется в `flow/handlers.py:on_message` после команды статуса
и до классификации. Мгновенное подтверждение («Принял, определяю…»)
для вопроса о правах — своё: «Ищу в нормативах…».

**Ответ.**

- текст вопроса маскируется (`mask()` → `MaskedText`) до поиска и LLM;
- поиск — `knowledge.search(masked, k=5)` с фильтром действующей редакции и
  `management_company_id` дома жителя;
- LLM — общий клиент процесса `get_llm_client()` (не создавать новый:
  иначе не работают лимит частоты и размыкатель, урок ревью CLASSIFY);
- схема ответа (pydantic):

| Поле | Тип | Правило |
|---|---|---|
| `sufficient` | bool | `false`, если во фрагментах нет ответа на вопрос |
| `answer` | str ≤ 700 символов | Простым языком, без номеров актов и пунктов в тексте — ссылки добавляет код |
| `cited_fragments` | list[int] | Номера показанных фрагментов `[1..N]`, на которые опирается ответ (тот же приём, что в CLASSIFY-001, `confirm_citations`) |

- промпт — `rights/prompt.py`, `PROMPT_VERSION` своя: отвечать **только**
  по показанным фрагментам; если их недостаточно — `sufficient = false`;
  не упоминать нормы, которых нет во фрагментах; не давать советов «на
  всякий случай».

**Проверка основания — отказ вместо ответа, если:**

- `sufficient = false`;
- после `confirm_citations` не осталось ни одного подтверждённого фрагмента;
- в `answer` встречается номер акта (`№\s?\d+`) или «п. N», которого нет
  среди подтверждённых фрагментов (модель проговорилась о норме, которой
  ей не показывали).

Отказ: «В нормативах, которые я знаю, прямого ответа на этот вопрос нет.
Вы можете уточнить в своей управляющей компании (АДС: <телефон>) или в
жилищной инспекции вашего региона.» Никакого частичного ответа модели.

**Формат ответа жителю:**

```
<answer>

Основание:
• ПП РФ №354, Прил. 1 п. 4
• ПП РФ №354, п. 31 пп. н

Это справка по нормативам, а не юридическая консультация.
```

Ссылки — `RetrievedChunk.label` подтверждённых фрагментов (полная ссылка
с документом), а не короткий `ref`.

**Отказы инфраструктуры.**

| Отказ | Поведение |
|---|---|
| `LlmError` (любой) | Честно: «Сейчас не могу подобрать ответ по нормативам — попробуйте позже.» + контакт АДС УК. Ответа по прототипам или по кэшу здесь нет (§6.4: функция отключается) |
| Qdrant недоступен | То же сообщение, без вызова LLM |

Основной сценарий (жалобы) не затрагивается ни одним из этих отказов.

**Журнал** — новая таблица `rights_logs` (миграция `0009`):
`id`, `inbound_event_id` (FK), `question_masked`, `refused` (bool),
`refusal_reason` (`insufficient` / `no_citations` / `unknown_norm_in_answer`
/ `llm_unavailable` / `kb_unavailable`), `used_chunk_ids` (JSON),
`model_name`, `prompt_version`, `kb_version`, `latency_ms`, `created_at`.
Только маскированный текст вопроса; текст ответа модели **не** хранится
(может пересказывать вопрос) — достаточно ссылок и признака отказа.

**Известная дыра (CLASSIFY-003).** Бесплатная модель
`nex-agi/nex-n2.5-mini:free` нестабильно заполняет `cited_fragments` —
для RIGHTS это будет означать частые отказы. Это ожидаемо: **не**
ослаблять проверку основания, чтобы «поднять» долю ответов, — выбор
модели решается в CLASSIFY-003. В тестах — `FakeLlmClient`.

**Ручная проверка** — `scripts/rights_demo.py "могут ли отключить
горячую воду на месяц?"` (по образцу `scripts/classify_demo.py`): ответ,
ссылки, признак отказа, задержка. Запускать только с ключом OpenRouter из
`.env`; вызовы тратят суточный лимит бесплатной модели — несколько
прогонов, не циклы.

## Критерии приёмки

- [ ] Сценарии 1–10 покрыты тестами и проходят (`FakeLlmClient`).
- [ ] Детектор не перехватывает вопросы «кто/кому» и описания проблем (отрицательные тесты).
- [ ] Ответ без подтверждённого фрагмента или с «чужой» нормой в тексте не показывается жителю.
- [ ] Ссылки в ответе — полные (`label`), только подтверждённые.
- [ ] В LLM и в `rights_logs` — только маскированный текст; текст ответа модели не хранится.
- [ ] Используется общий LLM-клиент процесса.
- [ ] Миграция `0009` применяется и откатывается.
- [ ] Живой прогон `rights_demo.py` на 3–5 вопросах — результат (включая отказы) в закрытии.
- [ ] `bash scripts/check.sh` проходит.
