# CLASSIFY-001 — Классификация обращения: RAG + LLM + порог уверенности

| Поле | Значение |
|---|---|
| ID | `CLASSIFY-001` |
| Статус | `done` |
| Требования | architecture.md §4 (две оси, порог, обоснование), §5.6 (`classification_logs`), §6.2 (п. 1, 3–5), §10 (строки OpenRouter и Qdrant), §11 (маскирование); idea_and_scope.md шаг 3.5 (отличие — ответ на вопрос «кому») |
| Зависимости | KB-001, LLM-001, MASK-001 |
| Блокирует | CLASSIFY-002, FLOW-001, EVAL-002, RIGHTS-001 |

## Цель

Свободный текст жителя превращается в строгое решение: `problem_type`,
`responsibility_zone`, `confidence` и основание — пункты нормативов, на
которые решение опирается. По порогу уверенности решение попадает в одну
из трёх веток: автоматическая маршрутизация, один уточняющий вопрос или
честное «не берусь определить». Это ядро продукта — ответ на вопрос
«кому», которого нет у ГИС ЖКХ и «Госуслуг Дом».

Результат задачи — сервис классификации с журналом и проверкой на живой
модели, **без** диалога в MAX (FLOW-001), кэша и деградации без LLM
(CLASSIFY-002).

## Scope

### Входит

- модуль `src/upravdom/classifier/`: схема решения, построитель промпта,
  сервис `classify()`, выбор ветки по порогу;
- поиск нормативов через `knowledge.search` с фильтром действующей
  редакции и `management_company_id` дома;
- вызов LLM через порт `LlmClient` (LLM-001), вход — только `MaskedText`
  (MASK-001);
- проверка основания: LLM может сослаться только на пункты, которые ему
  реально показали;
- второй проход с ответом на уточняющий вопрос;
- запись каждого решения в `classification_logs`;
- вынос эмбеддинга запроса из event loop (`asyncio.to_thread`) и прогрев
  модели при старте — замечание ревью KB-001;
- минимальная обработка отказа LLM: решение ветки «не уверен» с
  `fallback_used = true` (полная деградация — CLASSIFY-002);
- скрипт ручной проверки `scripts/classify_demo.py`.

### Не входит

- диалог, кнопки, создание заявки — FLOW-001, TICKET-001;
- семантический кэш и классификация без LLM по similarity search —
  CLASSIFY-002;
- измерение точности и калибровка порогов — EVAL-002 (на наборе EVAL-001);
- ответы на вопросы о правах — RIGHTS-001.

## Технические требования

**Контракт.**

```python
async def classify(
    text: str,
    *,
    house_id: uuid.UUID,
    inbound_event_id: uuid.UUID,
    session: AsyncSession,
    clarification: Clarification | None = None,
    llm: LlmClient | None = None,
) -> ClassificationResult
```

`ClassificationResult`: `problem_type`, `responsibility_zone`,
`confidence`, `branch` (`auto` / `clarify` / `unknown`), `citations`
(список `RetrievedChunk`: `chunk_id`, `ref`, `text`), `clarifying_question`
и `clarifying_options` (для ветки `clarify`), `fallback_used`,
`log_id`. Сырой текст внутри сервиса маскируется первым же шагом, дальше
живёт только `MaskedText`.

**Схема ответа LLM** (pydantic, валидируется всегда — LLM-001):

| Поле | Тип | Правило |
|---|---|---|
| `problem_type` | str | Один из кодов `problem_types` (читаются из БД при старте, не хардкодятся — справочник переменная часть, architecture.md §4) |
| `responsibility_zone` | enum | `uk` · `rso` · `owner` · `municipality` · `unknown` |
| `confidence` | float 0..1 | |
| `cited_fragments` | list[int] | Номера показанных фрагментов `[1..N]` (после ревью; строки ссылок модель пересказывала — см. закрытие) |
| `reasoning` | str ≤ 300 символов | В журнал, не жителю |
| `clarifying_question` | str \| null | Обязателен, если модель не уверена между двумя вариантами |
| `clarifying_options` | list[str], 2–4 | Короткие варианты ответа для кнопок («В квартире после крана», «На стояке в подъезде») |

**Проверка основания — защита от «уверенной выдумки» (§4).** Номера из
`cited_fragments`, которых не было среди показанных фрагментов, отбрасываются.
Если после этого не осталось ни одной ссылки, `confidence` ограничивается
значением ниже `CLASSIFY_CONFIDENCE_HIGH`: без нормы, которую можно
показать жителю, автоматическая маршрутизация запрещена. Код неизвестного
`problem_type` превращается в `other` + ветка `unknown`.

**Промпт** — `classifier/prompt.py`, константа `PROMPT_VERSION` (пишется в
журнал и участвует в инвалидации кэша, §6.3). Состав: роль и задача;
таксономия с определением каждого `problem_type` из справочника; правила
зон с опорой на нормы — граница «первое отключающее устройство / стык»
(ПП №491, п. 5), внутриквартирное оборудование после него — `owner`,
внешние сети до стены дома — `rso` (ПП №491, п. 8), территория за
границей участка — `municipality`; найденные фрагменты с их ссылками;
замаскированный текст жителя; требование ответить строго по схеме.
Примеры (few-shot) — только сочинённые и помеченные в коде как
сочинённые; **ни одной фразы из набора EVAL-001** — иначе метрика
EVAL-002 измерит память промпта.

**Пороги** — из настроек (`CLASSIFY_CONFIDENCE_HIGH = 0.75`,
`CLASSIFY_CONFIDENCE_LOW = 0.45`): `≥ HIGH` → `auto`; `[LOW, HIGH)` →
`clarify`, если модель дала вопрос и 2–4 варианта, иначе `unknown`;
`< LOW` → `unknown`. Граничные значения — тестом.

**Уточнение.** `Clarification(question, answer)` добавляется в промпт
вторым проходом. После уточнения ветка `clarify` невозможна: средняя
уверенность → `unknown` (кейс: не больше одного вопроса, иначе житель
застревает в диалоге).

**Отказы.**

| Отказ | Поведение CLASSIFY-001 |
|---|---|
| `LlmError` (любой) | `problem_type = other`, зона `unknown`, `confidence = 0`, ветка `unknown`, `fallback_used = true`. CLASSIFY-002 заменит это на similarity search |
| Qdrant недоступен | Классификация без фрагментов не выполняется: ветка `unknown` (§10) — маршрутизация без нормы запрещена правилом выше |
| Нет текста / только эмодзи | Ветка `unknown` без вызова LLM |

Ни один отказ не бросает исключение наружу: FLOW-001 всегда получает
решение и отвечает жителю.

**Журнал.** Одна строка `classification_logs` на каждый проход (включая
второй после уточнения): `message_masked`, решение, `confidence`,
`used_chunk_ids` (только подтверждённые), `model_name` — **фактически
ответившая** модель из `LlmResult`, `prompt_version`, `kb_version` из
манифеста KB, `latency_ms`, `cache_hit = false`, `fallback_used`.
`reasoning` модели не сохраняется нигде: колонки под него нет и ради
отладки она не нужна, а в лог приложения его писать нельзя — он может
пересказывать обращение.

**Event loop.** `embed()` синхронный и грузит модель на ~490 МБ. Поиск
вызывается через `asyncio.to_thread`, модель прогревается в `lifespan`
приложения. Проверка — тест, что во время `search` event loop продолжает
обслуживать другие корутины.

## Результат закрытия

- **Статус:** `done` (22.09.2026), локально без деплоя на VM.
- **Артефакты:** `classifier/{schema,prompt,service}.py`, `embeddings.warmup`,
  `retrieval` через `asyncio.to_thread`, `scripts/classify_demo.py`,
  unit + integration тесты.
- **check.sh:** 284 теста, OK.
- **Живой `classify_demo.py` (15 сочинённых фраз):**
  - модель: `nex-agi/nex-n2.5-mini:free`;
  - ветви: **auto=5**, **clarify=1**, **unknown=9**;
  - суммарно ~205 с (~14 с/фразу с RAG+LLM);
  - часть `unknown` — срабатывание фильтра оснований: модель парафразирует
    `ref`, совпадения нет → confidence ниже HIGH, без `auto`.
- **Отклонения:** в публичный контракт `classify()` добавлены обязательные
  `session` и опциональный `llm` (как у остальных сервисов с БД/тестами).
- **Follow-up:** CLASSIFY-002 (кэш + деградация); FLOW-001 / TICKET-001;
  при необходимости — смягчить сопоставление `cited_refs` ↔ `chunk.ref`
  без ослабления запрета на выдуманные пункты.
- **Исправления после ревью (22.09.2026):**
  - основание — номера показанных фрагментов (`cited_fragments`) вместо
    строк `cited_refs`: живой прогон дал 9 unknown из 15, в том числе из-за
    того, что модель пересказывала короткий `ref` («п. 5 абз. 1» →
    «ПП РФ №491, п. 5»), а сверка шла по точной строке и по ключу без
    документа (совпадающие `ref` разных актов затирали друг друга).
    Фрагменты в промпте подписаны номером и полной ссылкой;
    `PROMPT_VERSION = 2` (записи кэша версии 1 выводятся из оборота);
  - один `OpenRouterClient` на процесс (`get_llm_client`): раньше клиент
    создавался на каждое сообщение, и лимит 15/мин и размыкатель LLM-001
    в рабочем режиме не накапливали состояние;
  - `fallback_used` — только «решение без LLM»; ответ резервной модели
    больше так не помечается (какая модель ответила — `model_name`).
  - **Нужен повторный живой прогон `classify_demo.py`** на тех же 15
    фразах, чтобы подтвердить снижение доли `unknown`.
