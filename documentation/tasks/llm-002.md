# LLM-002 — Цепочка резервных бесплатных моделей вместо одной

| Поле | Значение |
|---|---|
| ID | `LLM-002` |
| Статус | `done` |
| Требования | architecture.md §2, §10; openrouter_api.md §5, §8, §10 |
| Зависимости | LLM-001, CLASSIFY-003 |
| Блокирует | нет |

## Проблема

Резерв был один — `OPENROUTER_MODEL_FALLBACK`, одна модель. К 28.09.2026 эта
модель **исчезла из бесплатного каталога**: на запрос приходит

```
404 {"error":{"message":"This model is unavailable for free.
The paid version is available now - use this slug instead: nex-agi/nex-n2.5-mini"}}
```

То есть на проде резерва фактически нет: когда основная модель не отвечает,
цепочка заканчивается мгновенным отказом, классификация деградирует на
similarity search, и житель получает «не берусь определить точно» вместо
разобранного обращения. Ровно эти три `LlmUnavailable` из 11 вызовов видны в
результате FLOW-005.

## Цель

Отказ или исчезновение одной бесплатной модели не выводит классификацию из
строя: в `OPENROUTER_MODEL_FALLBACK` список моделей, они пробуются по порядку,
перебор ограничен общим бюджетом времени.

## Scope

### Входит

- `OPENROUTER_MODEL_FALLBACK` — список через запятую; `Settings.llm_model_chain`
  собирает порядок перебора и убирает повторы;
- перебор всей цепочки в `OpenRouterClient.complete_json` (размыкатель на
  каждую модель уже был);
- общий бюджет `LLM_TOTAL_BUDGET_SECONDS` на всю цепочку;
- жёсткий срок на один вызов (`asyncio.wait_for` поверх таймаута httpx);
- подбор 3–5 резервов замером на реальном промпте;
- тесты на перебор, дедупликацию, бюджет и зависшую модель.

### Не входит

- `models[]` / `route: "fallback"` на стороне OpenRouter — решение LLM-001
  (свой вызов на каждую модель) не меняется: нужен явный `fallback_model_used`
  и однозначный `model_name` в журнале;
- повторы к одной и той же модели: отказ — повод идти к следующей, а не
  ждать ту же;
- смена основной модели.

## Технические требования

**Бюджет обязателен.** Прежняя граница держалась на размере цепочки: две
модели × 45 с = 90 с, меньше окна видимости inbound (120 с). С пятью
резервами это правило исчезает, а переживший окно перебор означает повторную
обработку того же сообщения. `LLM_TOTAL_BUDGET_SECONDS = 100` — 20 с запаса
на маскирование, поиск по базе знаний, запись и отправку.

**Таймаут должен быть сроком, а не паузой между байтами.** Read-таймаут httpx
отсчитывается заново на каждую порцию, а OpenRouter, пока ждёт провайдера,
присылает в тело keepalive-комментарии. На замере ниже вызов к
`nvidia/nemotron-3.5-lightning:free` прожил **104 с при лимите 40 с**. Поэтому
на каждый вызов накладывается `asyncio.wait_for`.

**Порядок цепочки — по провайдерам, а не по качеству.** Модели одного
провайдера отказывают одновременно (LLM-001, §10 openrouter_api.md), поэтому
следующая в списке — всегда у другого провайдера, а вторая модель Nvidia
стоит после чужих.

## Критерии приёмки

- [x] Отказ первых моделей не мешает ответить следующей — перебор идёт до конца.
- [x] Одна и та же модель в списке дважды не вызывается дважды.
- [x] Перебор обрывается по общему бюджету раньше окна видимости inbound.
- [x] Зависший вызов снимается по сроку, а не живёт минутами.
- [x] Состав цепочки подтверждён замером на реальном промпте.
- [x] `bash scripts/check.sh` проходит.

## Результат закрытия

**Закрыта 28.09.2026.**

`OPENROUTER_MODEL_FALLBACK` стал списком: `Settings.llm_model_chain` собирает
порядок перебора и убирает повторы, `complete_json` идёт по цепочке до первого
ответа. Размыкатель на каждую модель был с прошлой правки — модель, которая
перестала отвечать, выпадает из перебора сама и не стоит по 45 с на каждом
сообщении.

**Цепочка** (обоснование и полный замер — openrouter_api.md §11):

| № | Модель | Локально | С пилотной VM |
|---:|---|---|---|
| основная | `nvidia/nemotron-3-super-120b-a12b:free` | 2/3, 13.7 с | 2/2, 9.8 с |
| 1 | `poolside/laguna-s-2.1:free` | 3/3, 5.0 с | 2/2, **4.6 с** |
| 2 | `liquid/lfm-2.5-2.6b:free` | 3/3, 17.9 с | 2/2, 6.5 с |
| 3 | `dots-studio/dots-3-note-preview:free` | 2/3, 8.9 с | 2/2, 8.9 с |
| 4 | `cohere/north-mini-code:free` | 3/3, 7.4 с | 2/2, 7.9 с |
| 5 | `nvidia/nemotron-3-ultra-550b-a55b:free` | 2/3, 21.4 с | 1/2, таймаут |

Порядок — по прогону **с VM**: продукт работает оттуда, и задержки там другие
(`liquid` локально самая медленная, с VM — вторая по скорости).

Из 16 бесплатных моделей каталога отвечать на рабочем промпте смогли семь;
`qwen/qwen3.8-27b:free` не взят как самый медленный при том же результате,
остальные отсеклись по 403/400/429 и `ResourceExhausted`.

**Найдено по ходу — таймаут не ограничивал вызов.** `nvidia/nemotron-3.5-lightning:free`
держал соединение **103.8 с при лимите 40 с**: read-таймаут httpx считается
заново на каждую порцию байт, а OpenRouter, пока ждёт провайдера, присылает в
тело keepalive-комментарии. С цепочкой из шести моделей это опаснее, чем с
двумя, поэтому на каждый вызов надет `asyncio.wait_for`, и таймаут стал общим
сроком. Тест — `test_hanging_model_is_cut_by_wall_clock`.

**Масштаб проблемы на проде** (пилотная VM, 28.09.2026): в
`classification_logs` 21 запись, 15 ответила основная модель, **6 прошли без
модели вообще** (`fallback_used = true`, `model_name` пуст) — резерв к тому
моменту уже отвечал 404 «unavailable for free».

**Отклонение от постановки:** резервов пять, а не «3–5 на выбор» — все пять
подтверждены замером, а бюджет не даёт цепочке стоить больше прежних 90 с.

**Оговорка про строгую схему.** `strict: true` соблюдают не все: на коротком
служебном промпте без образца ответа `laguna-s` и `north-mini-code` вернули
только `problem_type` и `cited_fragments`, и pydantic такой ответ отклонил. На
рабочем промпте, где образец заполненного ответа есть всегда (CLASSIFY-003),
обе заполняют схему целиком. То есть образец в промпте несёт нагрузку и
убирать его нельзя — записано в openrouter_api.md §11.

**Выложено на VM 28.09.2026** вместе с FLOW-005 (обе правки до этого были
только локально). `.env` менялся одновременно с кодом: старый образ понял бы
список через запятую как одно имя модели. Проверено на проде:

- `/health` и `/ready` — 200, `postgres: true`, `qdrant: true`;
- контейнер видит цепочку из шести моделей и бюджет 100 с;
- перебор с подменённой мёртвой основной моделью — ответила резервная
  (`fallback_used = true`), обращение разобрано;
- `nemotron-3-ultra` на одном из вызовов снялся ровно на 45.0 с — жёсткий срок
  работает на живом провайдере, а не только в тесте.
