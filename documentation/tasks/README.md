# Задачи проекта

Каталог содержит детальные постановки разработки продукта «Цифровой Управдом».
Порядок и статусы задач определяются только в
[progress_dev.md](../progress_dev.md).

## Правила

1. Одна задача — один законченный проверяемый результат.
2. Файл называется `{module}-{NNN}.md`, ID пишется в верхнем регистре.
3. Обязательный каркас един для всех задач; дополнительные технические разделы разрешены.
4. Неизвестные внешние API (MAX Bot API, OpenRouter) не выдаются за подтверждённый контракт без проверки.
5. Одновременно выполняется одна основная задача, если независимость не отмечена явно.
6. Если в `progress_dev.md` нет `ready` — не брать `blocked`/`planned` без явного запроса.
7. Статус меняется одновременно в task-файле и `progress_dev.md`.
8. `done` допустим только после выполнения проверок и заполнения результата закрытия.

## Шаблон

```markdown
# MODULE-NNN — Название

| Поле | Значение |
|---|---|
| ID | `MODULE-NNN` |
| Статус | `planned` |
| Требования | Раздел idea_and_scope.md / architecture.md |
| Зависимости | Нет / TASK-001 |
| Блокирует | TASK-002 / не определено |

## Цель

Один наблюдаемый законченный результат и его ценность.

## Scope

### Входит

- ...

### Не входит

- ...

## Технические требования

Только необходимые контракты, модели, алгоритмы и ограничения.

## Артефакты

| Артефакт | Назначение |
|---|---|
| `path` | ... |

## Критерии приёмки

- [ ] Проверяемое условие.
- [ ] Ошибочный сценарий проверен.

## Проверка

Точные воспроизводимые команды и ожидаемый результат.

## Результат закрытия

Заполняется после выполнения:

- изменённые артефакты;
- фактические проверки;
- отклонения от постановки;
- follow-up задачи.
```

## Статусы

- `planned` — постановка существует, старт ещё не разрешён;
- `ready` — задача полностью готова к выполнению;
- `in_progress` — выполняется;
- `blocked` — указан конкретный блокер;
- `done` — критерии подтверждены;
- `cancelled` — отменена с причиной.

Очередь и статусы — только в [progress_dev.md](../progress_dev.md).
