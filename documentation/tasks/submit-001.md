## Фиксация версии

Commit hash не записывается в этот файл: он будет хешем последнего коммита,
то есть коммита, включающего сам файл. Значение берётся после финального
пуша и вписывается **на первый слайд презентации**:

```bash
git rev-parse HEAD
```

После дедлайна переданная версия не изменяется — правки в репозиторий до
объявления результатов онлайн-этапа не вносятся.

## Порядок проверки для жюри (краткий)

1. Открыть `t449_hakaton_max_bot` в MAX, перейти по deep-link дома, дать согласие.
2. Написать «в подъезде на лестничной площадке не горит свет второй день» →
   заявка с номером, адресатом, сроком и основанием.
3. «статус» → список заявок; «что в доме» → обращения дома.
4. «/права за сколько часов приедет мастер после заявки об аварии» → ответ
   по нормативу или документу УК.
5. Локально: `cp .env.example .env && docker compose up --build -d`, затем
   `curl http://localhost:8000/ready`.

## Что осталось за командой

- вписать commit hash и значения `MAX_BOT_TOKEN`, `MAX_WEBHOOK_SECRET`,

- не коммитить заполненную презентацию в репозиторий.

## Известные ограничения на момент сдачи

Перечислены в README и на последнем слайде: нестабильность бесплатной модели

калибровка порога на том же наборе, отсутствие реальных интеграций и рабочего
места диспетчера, отсутствие мини-приложения и вложений-фото.
